# 文档排版规范(所有角色适用)

> 所有 agent 产出的文档都按本规范排版。本文件由负责人维护,agent 只读。

## 1. 文件
- Markdown,UTF-8,文件名固定为模板名(如 `01-product.md`),一份文档一个文件。
- 不新增、不重命名模板文件;需要新文件时写入 issues.md 请求。

## 2. 头部
- 文件开头是 YAML 头部,字段固定:文档、状态、版本、上游依据、作者角色、日期、详细程度。
- 状态只用:草稿 / 待确认 / 已冻结。日期格式 `YYYY-MM-DD`。
- 头部之后紧跟一行"模板说明"(模板里有),**填写正式文档时删除**。
- 例外:变更文件夹内的文档,头部字段以各自模板为准(用"变更、基线版本"代替"上游依据"与"详细程度");`docs/issues.md` 没有头部。

## 3. 标题与章节
- 文档标题由头部的"文档"字段表示,正文从二级标题 `##` 开始,最多到四级 `####`。
- **章节编号与标题照抄模板,不得改号、不得删除章节、不得调整顺序。**
- 章节不适用时,保留标题,正文写"不适用:原因"。
- 标题后的 `★` 保留(标明轻量版保留的章节)。轻量版里非 ★ 章节整节省略(门禁检查与自检清单始终保留),并在文末写"轻量版省略的章节:编号列表"。

## 4. 填写说明行
- 模板里每个二级标题、以及独立成表的三级标题下有一行以 `> 说明:` 开头的引用,告诉你该写什么、怎么算写好。
- 它是给填写者看的,**不是正文**。填写正式文档时**删除所有说明行**,保留标题、表头和填好的内容。

## 5. 表格
- 列名和列顺序照抄模板,不得增减。例外:01 权限矩阵的角色列按实际角色增减。
- 空单元格写 `—`,不留空。需要待确认的写"待确认"。
- 一个单元格只写一个事实,不超过 80 字;更长的内容改用列表,放在表格下方并在单元格里引用编号。
- 状态列按表的语义取值:信息类表(00 等)用 已确认 / 待确认 / 冲突;任务状态用 未开始 / 进行中 / 完成;问题状态见 `docs/issues.md` 表头。
- 优先级只用:必须 / 应该 / 可以。严重度只用:严重 / 一般 / 轻微。

## 6. 编号与引用
- 编号格式:`FR-001`、`NFR-001`、`BR-001`、`Q-001`、`T-001`、`TC-001`、`BUG-001`、`ADR-001`、`CHG-001`,三位数字,不复用。
- 引用其他条目时写编号,不复述内容。
- 来源标注格式:`[来源: 文件/章节/人名@日期]`;推断内容标 `[假设]`。

## 7. 列表、代码、图
- 无序列表用 `-`,有序列表用 `1.`,复选框用 `- [ ]` 与 `- [x]`。
- 代码块必须标注语言(`bash`、`sql`、`yaml`、`json`、`mermaid`)。
- 流程图、时序图、状态图、ER 图用 `mermaid`;文字线框用不带语言的代码块。
- 命令一条一个代码块。

## 8. 文风
- 中文为主,专有名词、缩写保留原文。
- 句子短,一句一事;用具体数值和条件,不用"等、相关、适当、快速"。
- 不写套话和总结性空话(如"综上所述"),不加表情符号,不滥用加粗。
- 数字用阿拉伯数字;日期、版本号、编号按上面的格式。

## 9. 交付
- 文末固定有"自检清单",逐项标 通过 / 未通过,未通过写原因。
- 不得在文档里写模板没有的章节;额外的发现写入 `docs/issues.md`。
