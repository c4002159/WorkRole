# 测试规范清单

> 参考方向:ISO/IEC/IEEE 29119(软件测试)、GB/T 9386(测试文档)、ISTQB 术语、OWASP ASVS(安全检查项)。
> 目前没有公司测试规范,本清单以行业规范为基线。来源版本的核对情况、条目状态(试行/正式/废弃)和沉淀流程见 `INDEX.md`。新增条目编号延续(T21 起)。

## 1. 用例
- T1 每条用例有编号、对应的 FR 或 NFR、前置条件、操作、预期结果。
- T2 一条用例只验证一个目的;用例之间相互独立,可单独重复运行。
- T3 每条 FR 的每组验收标准至少一条正常用例,另补边界、异常、越权用例。
- T4 预期结果必须可判定(具体值、具体提示、具体状态),不写"正常显示"。
- T5 用例只依据 01 和 02 接口契约编写,不依据源码实现。

## 2. 测试数据
- T6 使用脱敏或构造的数据,不用真实客户数据。
- T7 测试数据可重新生成,构造规则写在 03 里。
- T8 数据校验类用例至少覆盖:缺列、空值、重复、格式错误、超大文件。

## 3. 执行与报告
- T9 每次执行记录:提交号、环境、时间、执行者。
- T10 失败必须附原始输出,不得转述。
- T11 没跑的测试写"未执行"及原因,**不得写成通过**。
- T12 追溯矩阵每次执行后更新:FR → TC → 结果。
- T13 禁止放宽断言、跳过用例、修改被测代码来通过测试。

## 4. 缺陷
- T14 分级:
  - 严重:数据错误、安全漏洞、主流程不通、数据丢失
  - 一般:功能不符合验收标准但有绕行办法
  - 轻微:文案、样式、不影响使用的瑕疵
- T15 缺陷记录含:BUG 编号、对应 TC、严重度、复现步骤、实际结果、预期结果、证据。
- T16 测试 agent 只记录缺陷,不修复。

## 5. 上线前测试清单(03 §4 逐项判断是否适用)
单元、接口、集成、端到端、回归、数据校验、权限与越权、安全(注入/XSS/文件上传/密钥泄露)、性能、兼容性、AI 输出(数字可追溯/无编造/提示词注入)、备份恢复与回滚演练、用户验收、上线检查。
- T17 "不适用"必须写理由。
- T18 阈值由我确定,不得自己编。

## 6. 准入与准出
- T19 准入:01 与 02 已冻结;代码已提交;测试环境可用。
- T20 准出:无严重缺陷;一般缺陷有处理决定;追溯矩阵无未覆盖的"必须"需求;未执行项已说明并经我确认。

## 7. 必须由人确认的项
安全测试的判断、性能阈值、用户验收签字、备份恢复演练、合规与备案。
