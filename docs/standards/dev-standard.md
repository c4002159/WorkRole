# 开发规范清单

> 本清单是通用底线,**不替代你们公司的开发手册**。
> 技术栈定下来后,在第 8 节补上栈专项规范(如阿里巴巴 Java 开发手册、PEP 8、前端 ESLint 规则),并把公司手册里的硬性条目提炼成一行一条加进来。
> 第 3 节的数据库条目来自我对通行 MySQL 规约的记忆,**未核对原文**,定稿前请对照公司或阿里云的现行规范。

## 1. 通用代码
- D1 命名表达含义,不用拼音缩写和单字母(循环变量除外)。
- D2 函数只做一件事,过长时拆分;不写魔法数字,常量集中定义。
- D3 注释写"为什么"而不是"做了什么"。
- D4 异常不得吞掉:要么处理,要么向上抛,并记录日志。
- D5 不留调试代码、被注释掉的代码、未使用的依赖。
- D6 所有外部输入视为不可信,在边界处校验。

## 2. 接口
- D7 先有 OpenAPI 契约,后有实现。实现与契约不一致算缺陷。
- D8 统一响应结构和错误码,错误信息不泄露内部细节。
- D9 列表接口必须分页;写接口考虑幂等。
- D10 接口变更先改契约并写 issues.md,不得先改代码。

## 3. 数据库
- D11 表名、字段名小写加下划线;表必有主键、创建时间、更新时间。
- D12 字符集统一 utf8mb4;金额用定点小数(decimal),不用浮点。
- D13 禁止 `select *`;禁止没有 where 条件的 update 与 delete。
- D14 索引命名约定(普通索引 idx_ 前缀,唯一索引 uk_ 前缀);为查询条件和关联字段建索引,并说明理由。
- D15 所有 SQL 参数化,禁止字符串拼接。
- D16 表结构变更用迁移脚本,可回滚,不在生产库手改。
- D17 外键与级联的使用以公司规范为准,在 02 里写明决定。

## 4. 安全
- D18 密钥、账号、令牌走环境变量或密钥管理,不进代码和仓库。
- D19 文件上传校验类型、大小、内容,保存路径不可被用户控制。
- D20 鉴权在服务端完成,不依赖前端隐藏按钮;每个接口按权限矩阵校验。
- D21 输出到页面的用户内容必须转义,防 XSS。
- D22 日志不记录密码、令牌、手机号全量等敏感信息。
- D23 依赖要锁定版本,新增依赖需有任务依据。

## 5. 日志与可观测
- D24 关键操作(登录、导入、状态变更、权限变化)写操作日志:谁、何时、做了什么。
- D25 错误日志含请求标识,便于定位。

## 6. 前端
- D26 使用 02 里选定的组件库,不自造基础组件;样式按 02 的界面规范。
- D27 页面必须实现 01 原型里的四种状态(空、加载、出错、无权限)。
- D28 前端校验只用于体验,服务端校验不可省略。

## 7. 提交与交付
- D29 提交信息带编号:`T-xxx FR-xxx 简述`。
- D30 一个提交对应一个任务;不混入无关改动。
- D31 提交前必须通过:格式检查、静态检查、单元测试、该任务验证命令。命令清单在 02 里写明。

## 9. AI 功能专项(本项目有 AI 生成结论时适用)
- D32 所有数字由代码计算,模型只负责写文字说明。
