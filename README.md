# 四角色 agent 协作骨架

分析 → 产品 → 开发 → 测试 → 你验收 → 上线。
记忆放在文件里,对话随用随开,每个角色、每个任务新开一个对话。

## 一次性准备
1. 把整个 `workflow-kit/` 里的内容复制到你的项目仓库根目录。
2. `git init`,提交第一版。
3. 在 `docs/standards/` 里补上公司的产品、开发、测试规范(尤其 dev-standard 第 8 节)。
4. 用 Codex 打开项目目录。Codex 会读取根目录 `AGENTS.md`(以你安装的版本行为为准)。

## 每个阶段的第一条消息(复制,替换中括号)

**1. 分析(首轮)**
```
角色:分析。任务:模式 A。产品描述如下:[粘贴]。
```
**1. 分析(整理采集记录)**
```
角色:分析。任务:模式 B。采集记录如下:[粘贴]。
```
**2. 产品**
```
角色:产品。00 已冻结。任务:先写 01a 竞品分析,再写 01 产品需求与原型。详细程度:[完整/轻量]。
```
**3. 开发(写 02)**
```
角色:开发。01 已冻结。任务:阶段一,写 02 技术方案。详细程度:[完整/轻量]。
```
**3. 开发(编码)**
```
角色:开发。02 已冻结。任务:阶段二,做 T-003。
```
**4. 测试(写 03)**
```
角色:测试。01 已冻结。任务:阶段一,写 03。不要读 src/。
```
**4. 测试(执行)**
```
角色:测试。任务:阶段二,对提交 [提交号] 执行测试并出报告。
```
**4. 测试(写 04)**
```
角色:测试。任务:阶段三,写 04 验收与上线。
```

## 每次收工后你做三件事
1. 运行路径检查:`python scripts/check_paths.py <analyst|product|dev|test>`
2. 检查产出;没问题就把文档头部状态改成"已冻结",提交。
3. 处理 `docs/issues.md`:把问题路由给对应的人,把答复写回。

## 首次上线之后:每次变化走变更文件夹
`docs/00` 至 `docs/04` 成为基线,agent 不再直接改它们。

1. 创建变更文件夹:
```bash
python scripts/new_change.py 变更名称
```
2. 在 `docs/issues.md` 登记一条类型为"变更请求"的问题。
3. 依次启动,每步门禁由你确认后改为"已冻结":

**产品(C0、C1)**
```
角色:产品。任务:CHG-001,先写 proposal.md 的影响范围,我确认(C0)后再写 01-delta.md。
```
**开发(C2)**
```
角色:开发。任务:CHG-001,写 02-delta.md;01-delta 已冻结。
```
**开发(编码)**
```
角色:开发。任务:CHG-001 的 T-0xx。
```
**测试(C3、C4)**
```
角色:测试。任务:CHG-001,写 03-delta.md,执行测试,并写验收与上线增量。
```
4. 提交前运行路径检查,变更阶段要加 `--change`:
```bash
python scripts/check_paths.py dev --change
```
5. **归档(你来做)**:把 delta 合并进基线 01、02、03,更新版本号与追溯矩阵,再把文件夹移到 `docs/changes/archive/日期-CHG-xxx-名称/`。
   - 编号延续,不重编;废弃的需求和用例保留编号并标"废弃"或"作废"。

## 规则与规范怎么演进(你来管,不需要常驻的管理 agent)
- 规则文件(`AGENTS.md`、`docs/rules/`、`docs/standards/`)只有你能改;agent 发现问题,在 issues.md 提"规范建议"。
- **技术栈确定时**:开发 agent 会提"规范待补充"并停下。你把公司或阿里云的开发手册提炼成条目,补进 `dev-standard.md` 第 8 节,再让它继续。
- **每个里程碑后**做一次复盘,新开对话:
```
角色:维护。任务:复盘 [里程碑],范围为 issues.md 中编号 [Q-xxx 到 Q-yyy] 的规范建议与规范待补充,输出修订建议。
```
- 你审核 `docs/proposals/` 里的建议,采纳的由你自己改规则文件并提交,再把 issues.md 对应条目标为"已采纳"或"已拒绝"。
- 同类问题出现两次以上才加规则,避免规则越堆越多。

## 注意
- 上游没冻结,下游不开工。
- 不要把真实数据、账号、密钥提交进仓库。
- 标准条目里标了"未核对"的,定稿前对照公司或官方的现行规范。
